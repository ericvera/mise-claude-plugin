## Defects the dry runs exposed (all fixed)

1. `flow.md` execute ended with `mark <mise-dir> execute done`; the script rejects it (`execute is derived from tasks/done/ and is never marked`) — run A step 9 would have stopped on the error. Removed; the step ends when the last task file lands in `tasks/done/`, which `report` picks up.
2. With the spec skipped there is no task file, but `report` derives `tasks_remaining ["01_01"]`, so run A had nothing to hand the implementer and no file to move — `step:execute` forever. `flow.md` execute now writes `tasks/01_01_<slug>.md` from `goals.md` first.
3. Run B step 11: appending the new task id under `## Amendments` only (the format the file shows) left `tasks_remaining` empty — the amendment's work was skipped straight to adherence. The amendment rule now says the new ids go into the spec's `## Task index` with their task files.
4. `/mise:next quick <description>` called `route` before the mise directory existed → `{"error":"mise directory not found"}`, which SKILL.md tells the driver to relay and stop on. The route is now set once the run is open.
